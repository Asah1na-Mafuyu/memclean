# memclean

Windows 手动内存清理与任务管理工具，使用 C++17 / Win32 编写。提供中文界面，免安装，运行时只需一个 EXE。当前版本 **2.0.0**。

默认回收所选后台桌面程序的工作集，保护前台程序、Minecraft 和 Java。需要管理员权限的系统缓存清理集中在高级窗口，所有项目默认关闭。

## 功能

| 功能 | 行为 |
| --- | --- |
| 手动清理 | 自行选择后台进程，逐项执行并显示结果 |
| 前台保护 | 记录切回工具前使用的程序，每项执行前重新核对 |
| Minecraft 保护 | 保守识别 Java、常见游戏进程和启动器，并保护其子进程 |
| 高级清理 | 可选择低优先级待机列表、全部待机列表或系统文件缓存 |
| 任务控制 | 支持取消后续项目，同一会话避免多个实例并发清理 |
| 单文件运行 | 静态链接 C++ 运行库，无需安装 .NET、Java 或额外运行库 |
| 任务管理器 | 独立窗口，提供进程、性能、详细信息、启动项、用户、服务和本次运行统计七个页面 |

程序不会自动清理、注册自身开机启动或安装后台服务，也不内置联网、更新或上传逻辑。采样数据只保存在内存中；手动导出会写入所选 CSV 文件，手动停用 / 恢复启动项会修改对应注册表值。

## 任务管理器

在清理主窗口点击 **“打开任务管理器…”**，或执行：

```powershell
.\memclean.exe --taskmgr
```

| 页面 | 已实现功能 |
| --- | --- |
| 进程 | 搜索、列排序；CPU、工作集、读写 I/O、GPU、窗口和用户；正常关闭、结束进程、结束进程树、切换窗口、文件位置及属性 |
| 性能 | 最近 120 秒的 CPU、物理内存、磁盘读写、物理网卡收发、GPU 最忙引擎和提交内存图 |
| 详细信息 | 专用提交、线程、句柄、优先级、会话、父 PID、路径；查看命令行，设置优先级、CPU 关联性与节能 QoS |
| 启动项 | 枚举当前用户 / 所有用户 Run 值和启动目录；备份停用、恢复 Run 配置；打开 Windows 启动设置 |
| 用户 | 用户会话及可读进程的资源合计；查看用户进程，确认后断开或注销其他用户会话 |
| 服务 | 状态、PID、启动类型、账户；启动、停止、重启、暂停、继续和调整启动类型；转到对应进程 |
| 本次运行统计 | 窗口打开后观察到的进程 CPU 时间和累计读写 I/O；保留已退出记录，最多 5000 条 |

默认每 2 秒采样，可选择 1 / 2 / 5 秒、暂停刷新、窗口置顶、运行新任务和导出当前表格。`Ctrl+F` 搜索，`F5` 刷新，双击查看详情，右键打开操作菜单。最小化时停止定时采样。

**这是常用任务管理功能的独立实现，尚不等同于完整的 Windows 任务管理器。** 暂不提供系统历史应用数据库、启动影响评分、进程转储、等待链、每进程网络 / 真实磁盘归因、完整 GPU 显存与引擎视图、多处理器组关联性等功能。窗口顶部可直接打开 Windows 任务管理器。

进程 I/O 包含多类设备传输，不能当作磁盘读写量；“工作集”也不等同于系统任务管理器默认的专用工作集。启动目录只读，Run 配置存在不代表它已在 Windows 中启用。计数器缺失或权限不足时显示“—”。详见 [任务管理器说明](docs/TASK_MANAGER.md)。

## 系统要求

- Windows 10 1703 及以上，或 Windows 11；x64。
- 普通清理和任务管理器均可普通权限运行；高级清理单独请求管理员授权。服务、其他用户和高权限进程的操作由 Windows 权限控制，可在任务管理器中选择“以管理员身份重开”。
- GPU 计数器、节能 QoS 和系统启动设置的可用性取决于 Windows 版本、驱动和系统配置；不可用时明确报告或显示“—”。
- EXE 只依赖 Windows 自带 DLL，目前未进行商业代码签名。

## 使用

1. 双击 `memclean.exe`。
2. 切到想要保护的程序，再切回 memclean，核对窗口中的保护提示。
3. 检查勾选的后台进程，点击“清理所选后台程序”。
4. 在窗口下方查看结果。取消任务只停止尚未开始的项目。

“刷新列表”会重新选择所有符合条件的进程；手动取消的勾选仅对当前列表有效。完成清理后，同一窗口有 30 秒冷却时间。

**全局清理无法排除前台程序或 Minecraft，可能引起重新读取数据和卡顿。** 高级窗口默认不选任何项目，需要重新选择、执行并确认。

前台和 Minecraft 的自动保护适用于内存清理。任务管理器允许你明确选择并确认结束普通用户程序，包括游戏；结束操作会提示未保存数据可能丢失。系统、关键进程、工具自身和身份无法确认的目标受到额外保护。

## 清理原理与边界

普通模式调用 Windows 的 `EmptyWorkingSet`，请求把可分页页面移出后台进程的工作集。程序的数据仍然保留，再次使用时占用可能回升。该操作不能修复内存泄漏，也不保证提高游戏帧率。

高级模式通过原生接口处理待机列表，通过 `SetSystemFileCacheSize` 处理系统文件缓存。待机内存本来就属于系统可用内存，清空缓存不一定增加可用总量。

名称、路径与进程树识别无法覆盖任意改名的游戏程序；前台切换与系统调用之间也存在极短竞态。完整保护策略和实现边界见 [设计说明](docs/DESIGN.md)。

## 从源码构建

安装 Visual Studio 2022 / Build Tools 的“使用 C++ 的桌面开发”、Windows SDK，以及 CMake 3.24 或以上版本。在项目根目录使用普通权限 PowerShell：

```powershell
.\build.ps1
```

默认构建 Release x64 并运行核心测试，生成 **`dist/memclean.exe`**。

```powershell
.\build.ps1 -UiTests    # 同时验证界面
.\build.ps1 -SkipTests  # 仅构建程序
```

手动构建命令、格式约定和测试复现方法见 [开发说明](docs/DEVELOPMENT.md)。

## 项目结构

```text
src/         清理核心、任务管理采样与操作、Win32 界面
resources/   内嵌图标、程序清单和版本信息
tests/       核心测试、隔离测试进程与界面验证
docs/        设计、开发、验证记录与参考资料
build.ps1    一键构建及测试
```

`build/`、`dist/`、`work/`、本地配置和发布压缩包均由 Git 忽略。测试辅助程序只用于开发，不需要随应用分发。

已验证 43 项清理检查、62 项任务管理检查和 60 项界面检查。进程修改和回收测试只作用于隔离测试进程；启动项备份测试只使用隔离注册表键。管理员全局清理、真实服务变更和其他用户注销尚未在测试机器上执行，详见 [验证记录](docs/VALIDATION.md)。
