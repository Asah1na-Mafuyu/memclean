# 任务管理器

memclean 2.0 在同一个 EXE 中增加独立任务管理窗口。主窗口的“打开任务管理器…”会以 `--taskmgr` 启动另一个实例；也可直接使用这个参数。关闭任务管理窗口不会退出清理主窗口，打开任何窗口都不会自动清理、结束进程或修改系统配置。

## 操作

- 表头单击排序；搜索匹配表格文字，进程页面也匹配可执行文件路径。选择项通过 PID / 创建时间等身份键保持，避免刷新后把操作指向另一行。
- 默认每 2 秒采样，可改为 1 或 5 秒。最小化、菜单和模态对话框期间不发起新的定时采样。“暂停刷新”不阻止手动刷新和切换页面时读取数据。
- `Ctrl+F` 聚焦搜索，`F5` 刷新；双击或“详情…”显示可复制文字。进程页面按 Delete 会打开结束确认框。
- “运行新任务…”接受 EXE 路径及参数；带空格的路径需要引号，“浏览…”会自动加引号。使用 `CreateProcessW`，新进程继承此窗口的用户权限，不会自动提权。
- “以管理员身份重开”经 UAC 打开新的任务管理窗口，原窗口保留，不会自动重复任何操作。
- CSV 导出保留当前筛选和排序，使用 UTF-8 BOM，并转义引号、逗号及可能被表格软件当作公式的开头字符。

## 功能与系统接口

| 页面 / 操作 | 实现 |
| --- | --- |
| 进程枚举、父 PID、线程数 | Toolhelp 进程快照 |
| 进程 CPU、内存、I/O、句柄 | `GetProcessTimes`、`GetProcessMemoryInfo`、`GetProcessIoCounters`、`GetProcessHandleCount` |
| 用户、会话、可执行路径 | 进程令牌、`ProcessIdToSessionId`、`QueryFullProcessImageNameW` |
| 正常关闭 / 切换窗口 | 枚举可见顶层窗口，`WM_CLOSE` / `SetForegroundWindow` |
| 结束进程 / 进程树 | 校验身份与保护规则后，通过保留的进程句柄调用 `TerminateProcess` |
| 优先级 | `SetPriorityClass`；提供低、低于正常、正常、高于正常、高，不提供实时级别 |
| CPU 关联性 | `GetProcessAffinityMask` / `SetProcessAffinityMask`；只处理单处理器组 |
| 节能 QoS | `SetProcessInformation(ProcessPowerThrottling)`，设置执行速度节能请求；不等同于完整的系统效率模式 |
| 系统性能 | PDH 英文名称计数器、`GlobalMemoryStatusEx`、`GetPerformanceInfo`、`GetIfTable2` |
| 服务 | SCM 枚举、状态 / 配置查询，启动 / 控制 / 配置服务 API；仅枚举 Win32 服务，不管理驱动 |
| 用户会话 | WTS 枚举、查询、断开与注销接口 |
| 启动项 | 注册表 Run 值、已知启动目录；Run 配置停用与恢复见下节 |

命令行详情通过动态加载的 `NtQueryInformationProcess` 信息类 60 查询，校验返回缓冲区长度及指针范围。它不是稳定的公开 Win32 契约，失败时说明不可用，不改用注入或读取远程 PEB。

## 指标含义

| 指标 | 统计口径和限制 |
| --- | --- |
| 进程 CPU | 两次采样的内核 + 用户 CPU 时间之差，除以采样间隔和全部逻辑处理器数；范围 0–100% |
| 系统 CPU | PDH `Processor(_Total)\% Processor Time`；与系统任务管理器采用的处理器效用率口径可能不同 |
| 工作集 / 专用提交 | 前者是当前驻留物理页面，可包含共享页面；后者来自 `PrivateUsage`，是专用提交量，不是专用物理内存 |
| 进程读写 I/O | 进程 I/O 累计字节的差分，包含文件、网络及其他设备 I/O，不能当作磁盘吞吐 |
| 磁盘图 | PDH `PhysicalDisk(_Total)` 的读写字节速率，汇总物理磁盘 |
| 网络图 | 当前活动的物理网络接口累计收发字节差分；不包含虚拟接口与回环，不提供每进程网络归因 |
| GPU 图 | 对 GPU Engine 计数器按设备 / 引擎汇总进程贡献，取最忙引擎；跨多张显卡也取最大值，不是利用率相加 |
| 进程 GPU | 该 PID 的可用引擎计数器中的最大利用率；不是显存量，也不是全部引擎相加 |
| 提交内存 | `GetPerformanceInfo` 的 CommitTotal / CommitLimit，不等同于当前物理内存占用 |
| 用户合计 | 该会话中可读进程的 CPU 和工作集之和；权限不足会低估，共享工作集可能重复计算 |
| 本次运行统计 | 每个 PID + 创建时间自首次可读采样起的 CPU 时间、读写 I/O 增量；仅本窗口生命周期内保留，最多 5000 条 |

第一帧没有差分基线时，CPU / 速率显示“—”。读取失败不会伪装为零；历史计数器恢复可读后继续以首次有效基线计算。性能图保留最近 120 秒，磁盘 / 网络的第二条曲线使用虚线。刷新暂停期间没有采样点，重新采样的差分值覆盖这段间隔，不能据此还原暂停时的瞬时尖峰。

GPU 计数器依赖系统和驱动；未出现的进程 GPU 数据显示“—”。底部显卡名称来自连接桌面的显示设备枚举，不保证列出混合显卡机器上的全部渲染设备。这里的采样方式和列定义与 Windows 任务管理器并不完全相同。

## Run 启动项的备份与恢复

读取的 Run 路径为 `Software\Microsoft\Windows\CurrentVersion\Run`，范围包括当前用户 HKCU、所有用户 HKLM 的 64 位及 32 位视图。当前用户指此窗口所用账户；用其他账户的管理员凭据运行时，不代表原账户。

用户确认停用后：

1. 重新读取原始值，核对其注册表类型和原始字节与所选快照一致。
2. 在**同一 hive、同一注册表视图**的 `Software\memclean\DisabledStartup\Run` 保存同名副本。只处理 `REG_SZ` / `REG_EXPAND_SZ`，不展开或改写命令。
3. 读取副本校验后，再次核对原值，然后删除 Run 中的原值。

恢复沿相反方向进行。同名、不同内容的目标值会阻止操作，避免覆盖现有配置。中途失败时尽量保留原值或副本并报告，刷新后可以检查；命名互斥量防止同一会话的 memclean 实例并发修改。复制、校验、删除并非跨其他程序的原子事务，外部软件仍可能同时改写这些键，不应在其他启动项管理工具中同时编辑同一项目。

备份在重启及删除 EXE 后仍保留；可用 memclean 恢复，也可人工核对后把值移回原 Run 路径。所有用户的项目通常需要管理员权限。这个动作不影响已经运行的程序。

**“配置存在”只说明 Run 值存在。** Windows 自己的 StartupApproved 禁用状态、商店应用、计划任务、组策略、RunOnce 等并不由此功能管理；恢复 Run 值也不保证 Windows 会启用它。程序不修改未公开的 StartupApproved 二进制格式。启动目录项目只读，可打开所在目录或 Windows 启动设置继续管理。

## 操作保护

进程修改先重新打开目标并核对 PID + 创建时间，在同一个验证后的句柄上调用操作。系统账户、关键进程、基础系统进程、工具自身以及身份无法确认的目标仅可查看。进程树操作会先获取并验证整棵快照树的所有句柄，任一目标不安全则在开始结束操作之前拒绝；执行开始后不能回滚，随后新建的子进程不包含在此次快照中。

内存清理里的前台 / Minecraft 保护仍然有效。任务管理器属于用户明确选择的进程管理操作，允许确认后结束普通游戏程序，确认框会说明区别和数据丢失风险。优先级和关联性等变更作用于当前进程，不为下一次启动建立持久规则。

服务操作会重新核对服务路径和账户，按操作请求最小权限。重启先等待停止，再请求启动；最多等待目标状态 15 秒，不会强制停止依赖服务。请求发出后关闭窗口只能停止后续等待或后续步骤，已经完成的动作不会回滚。服务启动类型变更是持久设置，但不会直接改变当前运行状态。

断开 / 注销只允许其他已确认身份的用户会话，操作前重新匹配会话 ID、用户名和登录时间。当前会话和会话 0 不通过此界面注销。Windows 权限仍决定操作是否允许。

## 与系统任务管理器的差距

此版本覆盖七类常用页面及主要交互，仍有以下边界：

- 不重建系统应用历史数据库、不测量启动影响、不汇总应用包 / 浏览器标签页，也没有 Windows 11 的完整应用分组。
- 不进行 ETW 每进程网络 / 磁盘归因，不提供显存、每引擎和每物理磁盘 / 网卡的完整细分视图。
- 不提供转储、等待链分析、线程 / 句柄详细检查、进程挂起 / 恢复和系统实时优先级。
- 不绕过受保护进程或系统权限，不安装内核驱动；多处理器组关联性转交系统工具。
- 不监控远程计算机，不安装常驻服务，不持久保存性能历史和操作日志。

窗口顶部的“Windows 任务管理器”调用系统目录中的 `taskmgr.exe`。已执行与尚未执行的测试见 [验证记录](VALIDATION.md)。

## 源码分层

| 文件 | 职责 |
| --- | --- |
| `src/task_manager.h` | 数据模型、采样与操作接口 |
| `src/task_sampling.cpp` | 进程 / 性能采样、身份保护、差分与历史统计 |
| `src/task_actions.cpp` | 进程操作、关联性、优先级、QoS、命令行详情 |
| `src/task_system.cpp` | 服务和用户会话操作 |
| `src/task_startup.cpp` | 启动项枚举与 Run 值备份恢复 |
| `src/task_window.cpp` | 七页窗口、虚拟列表、图表、异步任务、菜单与 CSV |
| `src/task_dialogs.cpp` | 新任务、详情和 CPU 关联性对话框 |

采样和修改串行运行在工作线程，通过窗口消息交还结果；界面线程不直接遍历全部进程和服务。列表使用虚拟模式，不为每个刷新周期重复插入控件行。RAII 管理进程、令牌、服务、注册表和 PDH 句柄。现有清理核心继续由 `core.cpp` 管理，两部分共同编译到同一个 EXE。
