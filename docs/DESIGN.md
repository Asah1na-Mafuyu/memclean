# 设计说明

memclean 将 Windows 操作与界面分开：`src/core.cpp` 负责进程检查、保护策略和清理，`src/main.cpp` 负责用户交互、前台跟踪和工作线程。核心逻辑不依赖界面控件。

## 普通清理流程

1. 枚举进程与桌面窗口，读取进程创建时间、路径、用户、会话和工作集。
2. 根据当前前台身份计算保护集合，列表仅勾选可处理的后台进程。
3. 用户执行后，工作线程获得会话内命名互斥量，记录清理前的可用内存。
4. 每处理一个目标，都重新扫描和应用保护策略。重新打开进程后核对 PID 与创建时间，再检查前台是否发生变化。
5. 使用同一个验证后的句柄调用 `EmptyWorkingSet`，逐项记录结果。
6. 记录清理后的系统可用内存，工作线程结束后通知界面恢复按钮。

过程中的权限不足、进程退出、身份变化和保护规则命中会显示为跳过或失败。无法确认前台身份时，普通模式不执行回收。

## 保护策略

| 对象 | 识别方法 |
| --- | --- |
| 前台程序 | 记录最后一个本工具之外的前台进程；保护同一可执行文件路径的进程及其子进程 |
| Minecraft / Java | 常见进程名、启动器名称、`.minecraft` / `minecraft` 路径，以及它们的子进程 |
| 系统与管理员程序 | Windows 目录、关键进程状态、进程令牌中的提权状态 |
| 其他用户 / 会话 | 比对用户 SID 与会话 ID，不处理会话 0 |
| 其他保守排除 | 无法验证身份、没有桌面窗口关联、工作集小于 16 MB、清理工具本身 |

前台通过 `SetWinEventHook` 跟踪，并在实际执行时同步读取。工具自身成为前台时保留上一个外部程序，避免把“保护前台”错误地理解为只保护清理工具。

Java 识别偏保守，其他 Java 软件也被保护。游戏或运行时被任意改名、移动目录后，不保证仍可识别。用户可以取消列表中对应进程的勾选。

进程身份使用 PID 和创建时间共同确认；父进程创建时间必须早于或等于子进程，避免 PID 复用产生错误的进程树。Windows 没有把前台检查与工作集回收合并成原子操作的接口，因此两者之间仍有极短竞态。

## 工作集与内存统计

`EmptyWorkingSet` 请求系统尽可能移出目标进程工作集内的可分页页面，不判断业务层面的对象是否已经无用。数据仍可能留在物理内存缓存中，或由系统写回后再利用。共享页面仍被其他进程使用时，目标工作集下降也不等于回收了同样大小的物理内存。

再次访问可能产生软缺页，或需要读取磁盘的硬缺页。已申请的虚拟内存并未因此释放，内存泄漏和 Java 堆大小也不会得到修复。

界面通过 `GlobalMemoryStatusEx` 读取系统可用内存，包含待机、空闲和已清零页面。清理前后差值按大小比较后相减，显示增加或减少，避免无符号下溢。其他程序同时活动也会影响这个数值，所以不把差值宣称为工具独自释放的内存。

## 高级全局清理

提权仅启动同一个 EXE 的 `--advanced` 窗口。该参数不会直接清理；所有项目默认关闭，用户需要重新选择并确认。普通窗口无需等待提权子进程完成，取消 UAC 不会把普通任务锁住。

| 选项 | API / 参数 | 权限 |
| --- | --- | --- |
| 低优先级待机列表 | `NtSetSystemInformation`，信息类 80，命令 5 | `SeProfileSingleProcessPrivilege` |
| 全部待机列表 | 同上，命令 4；与低优先级选项互斥 | 同上 |
| 系统文件缓存 | `SetSystemFileCacheSize(SIZE_T(-1), SIZE_T(-1), 0)` | `SeIncreaseQuotaPrivilege` |

待机列表使用动态解析的原生接口，不属于稳定的公开 Win32 契约。权限在单个操作内启用并保存原状态，结束时恢复；检查 `ERROR_NOT_ALL_ASSIGNED`。原生失败记录 NTSTATUS，并正确映射为 Win32 错误，不依赖该调用后的 `GetLastError`。

全局缓存不能按进程排除，因此前台和 Minecraft 保护只适用于普通模式。程序不提供全系统工作集清空、修改页强制写回、注册表缓存回收或内存页合并。

## 生命周期与兼容性

- 枚举与清理在工作线程执行，通过窗口消息传递日志和结果。
- 取消仅在项目之间生效；已经进入 Windows 的调用不能中途撤销，已完成操作也不能回滚。
- 普通和高级实例使用相同的会话内命名互斥量；沿用早期版本的锁名称，避免与旧版本并发执行。
- 同一窗口在完成后限制 30 秒内重复执行；该冷却时间不跨进程持久化。
- RAII 负责关闭进程和令牌句柄、恢复权限、释放互斥量。目标句柄在身份核对与实际回收之间保持不变。
